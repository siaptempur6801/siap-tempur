## Coverage

The second pass widened the source review to the CPNS/TKA learning routes, result and diagnostic surfaces, assignment, event, purchase/pass, profile, practice/review flows, shared primitives, and admin shell/workspace components. The route inventory includes the existing marketing, account, legal, certificate, API, and admin route families so that marketing/admin/account styling is not accidentally pulled into learner overrides. Browser review on the local app covered CPNS dashboard/result/event, TKA tryout result, and the admin dashboard/question-bank workspace at the available desktop viewport; earlier checks also covered CPNS landing, focused practice, Mini Tryout, history, and TKA diagnostics. This deeper pass opened the CPNS profile and all TKA profile routes (SD, SMP, SMA), then inspected profile, history, and settings states at desktop and mobile widths. It exercised profile edit/cancel, password validation/cancel, delete-account cancel, and avatar-preview dismissal without submitting account changes. A read-only Chromium public E2E pass exercised CPNS landing navigation/anchors and sticky CTA behavior at seven viewport sizes, blog index/detail/not-found routes, and legacy admin workspace URL routing. Admin navigation and route context were inspected without changing records. No purchase, answer submission, sign-out, production write, or admin mutation was made.

The source scan found the main drift in learning and exam modes: marketing-sized headings and paper decoration on learner task pages, repeated ink-outline pills, bespoke exam overlays with movement, hard shadows, display typography, and incomplete dialog semantics. The deeper route check also found that CPNS result URLs were classified as active exam sessions by two broad path checks, while the nested session layout still forced result content into the full-screen exam frame. Those checks now match only the active session URL. The global learning contract now preserves rich-text article/editor heading hierarchy and functional 90-degree icon rotations while suppressing small decorative tilts. The admin shell groups Assessment/Content under Learning, Event/Instansi/Monitoring under Operations, Commerce/Users under Business, and Settings under System. Existing dedicated admin pages, URL context, and list/detail workflows were retained.

The flow audit found one additional mismatch: the CPNS dashboard recommendation selected the weakest section in its copy, but its deep link used a lowercase section key while the destination heading ID used uppercase text. The link now resolves through normalized lowercase heading IDs, so a learner lands at the recommended section instead of the top of the list.

The profile audit found that TKA payment history used the account's all-program order query even though token balances and usage are separated by program. Payment rows are now scoped to the active program while preserving all TKA level purchases for the same TKA account. Voucher claims now revalidate the dynamic TKA level layout/profile route instead of only the SMP page. History page query parameters are clamped back to the last available page instead of showing an empty page for an out-of-range URL. Payment labels now cover provider refund/chargeback states, and success notifications no longer claim verification succeeded when the status-sync action fails. Profile controls now use the shared native dialog for image viewing/cropping, show server validation errors beside the edit form, use Jakarta-local date bounds, and share the compact learning page header.

Active-session and result login redirects retain the requested route.

Read-only route inspection showed the flow from the CPNS hub into focused TWK/TIU/TKP practice, then Mini Tryout and Full Tryout. The choose-path deep links now match the learner route and normalized section IDs. Some route visits in the development browser displayed their loading skeleton during this review, so this follow-up is a broad source audit plus targeted interactive review, not a claim that every data-backed state was rendered in the browser.

The pass audit also found that SD had active purchasable packages even though its Mini and Full Tryout pages say those flows are not ready. The SD/SMA pass pages now show status and readiness copy, preserve existing entitlement dates, do not offer new packages, and do not load the payment script. On SMP Mini/Full Tryout cards, a disabled “Tempur Pass required” action now includes a direct package link; focus-drill errors that report an exhausted free quota do the same. The choose-path page also drops duplicate level links because the level switcher already provides that navigation. Dashboard question totals for SD/SMA are labelled “soal terdata” rather than implying they can currently be started.

Final validation for this follow-up: `npm run lint`, `npm run typecheck`, and `git diff --check` pass. ## 11 October full Admin Workspace follow-up

The audit covered the admin dashboard and 20 core list, detail-entry, and create routes across Assessment, Question Bank/readiness/review/articles, Event, Instansi, Monitoring/Reports, Products/Orders, Users/roles/access, and Settings/Audit Log. Each primary route returned HTTP 200 with one main H1. Read-only browser review at 1440×900, 1024×768, and 390×844 found no document-level horizontal overflow across those 21 routes. The mobile navigation dialog opened by keyboard, received focus, closed with Escape, and returned focus to its trigger. Existing staging data allowed read-only checks of a question edit page, product edit page, and order detail page. Assessment, Event, and Instansi detail routes could not be exercised because the staging lists had no matching records; the selected-assignment monitoring branch also remains unverified because the batch has no assignments.

This pass found and corrected three UI defects:

- The Article rich-text editor registered Link twice because Tiptap v3 `StarterKit` already includes Link. `StarterKit` now disables its built-in Link extension while retaining the explicit configured extension. The duplicate-extension browser warning is gone.
- The article cover URL field relied on placeholder text for its accessible name. It now has an explicit label, linked hint, and a descriptive upload action; the hidden file input also has a name.
- An existing staging product was still marked Active while its content readiness gate was incomplete. The status field's initial error copy incorrectly implied a failed activation attempt. It now explains the stored Active state and directs the admin to choose Draft or Diarsipkan before saving. The readiness gate itself is unchanged.

The same pass checked for named inputs and buttons on the route set; the article cover URL was the only visible field needing an accessible-name correction. The Product list's apparent unnamed buttons were hidden archive-confirmation controls inside closed disclosures, not visible actions. No product, article, question, order, assessment, event, or organization data was changed.

Validation after these changes: `npm run lint`, `npm run typecheck`, `git diff --check`, and an isolated `npx next build --webpack` all pass. Browser follow-up confirmed the cover URL is reachable by its explicit accessible name, Upload has a descriptive name, the product message describes the actual stored status, and the Article editor emits no console warnings or errors. This remains a UI/workflow audit rather than a backend/RLS/business-rule audit. Screen-reader certification, Safari/Firefox, physical mobile devices, and mutation workflows remain unverified.
