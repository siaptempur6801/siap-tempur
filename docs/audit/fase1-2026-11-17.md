# Audit fase 1 — alur bisnis & operasional (2026-11-17)

Branch `audit/fase1-2026-11-17` dari `main` (`c9b7afb`). Dasar audit: pembacaan kode, migration SQL,
workflow CI, dokumen, dan test lokal. **Tidak ada query ke staging/production, tidak ada kredensial
asli.** Perilaku konkurensi SQL (A-04) disimpulkan dari semantik `READ COMMITTED` dan belum
direproduksi di database. Lanjutan dari [`docs/audits/AUDIT_2026-11-17.md`](../audits/AUDIT_2026-11-17.md),
yang fokus pada keamanan; temuan di sana tidak diulang.

## 1. Ringkasan

- **Sehat:** akun/aktivasi, katalog & kebijakan akses, timer server dan double-start/submit, zona waktu WIB, isolasi Organisasi.
- **Berisiko:** komersial (A-01…A-06, A-12), skor/leaderboard (A-04, A-08), Event/Tryout Akbar (A-01, A-02, A-04, A-07), operasional (B-01…B-07).
- **Rusak:** tidak ada alur yang rusak total. A-03 sudah terbukti lewat test, tetapi baru berdampak setelah satu produk tiket memiliki lebih dari 100 order.
- **Verdict:** penjualan token TKA SMP (Direct) **layak bersyarat** (syarat: B-01, B-04, B-05). **Tryout Akbar berbayar belum layak** sampai A-01–A-04 dan A-07 diputuskan dan diperbaiki.

## 5. Kesenjangan operasional

- **Tidak dipantau:** kegagalan fulfill/webhook selain lewat log manual; error rate submit Event; cron berhenti (kini ada sinyal P-2/P-3, tetapi belum ada alert yang membacanya); kesehatan Redis (health hanya cek konfigurasi); attempt menggantung; saldo negatif.
- **Tanpa runbook:** rollback app/DB, restore backup, insiden Tryout Akbar (submit massal, ranking ulang, sertifikat), offboarding Organisasi, permintaan hapus data peserta, rotasi secret.
- **Tanpa rencana pemulihan:** restore PITR yang teruji, rekonsiliasi refund, finalisasi attempt kedaluwarsa, sinkron order per admin.
